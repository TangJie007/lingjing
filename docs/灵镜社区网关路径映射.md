# 灵镜社区 ↔ Gateway 路径映射

> 客户端基址：开发 `http://localhost:3080`（Gateway）；上游 OpenAPI：[`http://localhost:8000/docs`](http://localhost:8000/docs)（`LINGJING_UPSTREAM`，默认 `http://127.0.0.1:8000`）  
> 实现：`apps/gateway/src/middleware/proxy/lingjing-path-rewrite.ts`  
> 适配：`lingjing-adapt.ts`（请求/响应字段名）  
> 反代：`proxy.middleware.ts` + `proxy-routes.ts`  
> 单测：`apps/gateway/test/lingjing-path-rewrite.spec.ts`

前端与管理端**不直连** Python，统一走 Gateway（开发默认 `http://localhost:3080`）。社区前台路径带 `/api/lingjing` 前缀，管理端带 `/api/admin/lingjing` 前缀；网关改写后再 HTTP 反代到灵镜服务。

---

## 1. 流量总览

```
Browser / Admin SPA
        │  /api/lingjing/* 或 /api/admin/lingjing/*
        ▼
   Gateway :3080
        │  AuthMiddleware
        │    · /api/lingjing*     → 网关侧公开（JWT 可选，透传 Authorization）
        │    · /api/admin/lingjing* → 必须管理员 JWT
        ▼
   ProxyMiddleware
        │  rewriteLingjingPath(path, method)
        │  rewriteLingjingQuery(search)
        │  toPythonRequestBody(JSON)          // camelCase → snake_case
        │  条件注入 X-API-Key / X-COS-*
        ▼
   Lingjing Python :8000
        │  见 /docs、/openapi.json
        ▼
   adaptLingjingResponse → 前端信封 + snake → camel
```

| 配置项 | 含义 |
|--------|------|
| `LINGJING_UPSTREAM` | Python 基址，默认 `http://127.0.0.1:8000` |
| `LINGJING_PY_API_KEY` / `LINGJING_API_KEY` | 打向 `/api/admin/*` 时注入为 `X-API-Key` |
| `LINGJING_COS_SECRET_ID` / `LINGJING_COS_SECRET_KEY` | 历史 COS 头；壁纸相关路径可注入（现多以 R2 环境变量为准） |

路由归属（`proxy-routes.ts`）：

| 前端前缀 | Upstream |
|----------|----------|
| `/api/lingjing` | lingjing |
| `/api/admin/lingjing` | lingjing |
| `/uploads` | lingjing（静态上传文件直通） |

## 2. 改写规则约定

1. **只改 path**；query 由 `rewriteLingjingQuery` 单独处理。  
2. **方法敏感**：同一 path 可能因 METHOD 不同落到不同 Python 路由（如壁纸列表 GET vs 会员上传 POST）。  
3. **顺序敏感**：`favorites` / `downloads` / `mine` / `related` 等必须写在「单条壁纸」通配之前，否则会被误改成 `/api/public/wallpapers/favorites`。  
4. 前端命名偏业务（`wallpaper-categories`），Python OpenAPI 用短名（`categories` / `tags`）。  
5. 对照上游请以 [`http://localhost:8000/docs`](http://localhost:8000/docs) 为准；下表为网关当前实现快照。

## 3. 社区前台：`/api/lingjing/*` → Python

### 3.1 认证与会话

| 前端 | 方法 | Python（OpenAPI） |
|------|------|-------------------|
| `/api/lingjing/auth/*` | * | `/api/auth/*` |

常见子路径：`login`、`login-code`、`register`、`send-code`、`send-login-code`、`session`、`me`、`logout`、`check-in` 等。

### 3.2 存储与本地上传

| 前端 | 方法 | Python |
|------|------|--------|
| `/api/lingjing/storage/*` | * | `/api/storage/*` |
| `/api/lingjing/uploads` | POST 等 | `/api/uploads` |
| `/uploads/*` | GET | `/uploads/*`（不改写） |

会员壁纸直传典型链路：

1. `POST /api/lingjing/storage/presign-put` → `POST /api/storage/presign-put`  
2. 浏览器 **PUT** 到 R2 Presigned URL（不经网关）  
3. `POST /api/lingjing/storage/from-keys` → `POST /api/storage/from-keys`  
4. `POST /api/lingjing/wallpapers` → `POST /api/wallpapers`（仅入库 `file_key`）

### 3.3 公开资源（`/api/public/*`）

| `/api/lingjing/wallpaper-categories` | GET | `/api/public/categories` |
| `/api/lingjing/wallpapers` | GET | `/api/public/wallpapers` |
| `/api/lingjing/wallpapers/{id}` | GET | `/api/public/wallpapers/{id}` |
| `/api/lingjing/wallpapers/{id}/related` | GET | `/api/public/wallpapers/{id}/related` |

### 3.4 壁纸：特殊改写

| 前端 | 方法 | Python | 说明 |
|------|------|--------|------|
| `/api/lingjing/wallpapers` | **POST** | `/api/wallpapers` | 会员上传入库（需登录）；与公开 GET 列表区分 |
| `/api/lingjing/wallpapers/{id}/file-url` | GET | **`/api/admin/wallpapers/{id}/file-url`** | 例外：走管理端签发，便于注入 API Key / COS 头；公开签发端常因缺环境变量 503 |
| `/api/lingjing/wallpapers/{id}/download?proxy=1` | GET | 先改写到 public download，再由网关**跟随 302 同源流式转发** | `proxy` 不转发给 Python；用于页内进度下载 |

## 5. Query / Body / 响应适配

### 5.1 Query（`rewriteLingjingQuery`）

| 前端 | 上游 |
|------|------|
| `pageSize` | `page_size` |
| `categoryId` | `category_id` |
| `enabled` / `isActive` | `is_active` |
| `isDefault` | `is_default` |
| `sortOrder` | `sort_order` |
| `wallpaperId` / `announcementId` / `tagId` / `commentId` | 对应 `*_id` |
| `keyword` | `q` |
| `status=active\|disabled` | `is_active=true\|false` |
| `proxy` | **丢弃**（仅网关下载代理用） |
| 其它 camelCase | 自动转 snake_case |

### 5.2 请求体（`toPythonRequestBody`）

- 通用 camelCase → snake_case  
- 别名：`enabled` → `is_active`，`isDefault` → `is_default`，`account` → `username`  
- 省略：`confirmPassword`

### 5.3 响应（`adaptLingjingResponse`）

- 统一/保持 `{ ok, data, error }` 信封  
- snake_case → camelCase；`is_active` → `enabled`  
- 认证、社区用户列表等有额外字段归一化

## 6. 头注入策略

| 条件 | 行为 |
|------|------|
| 改写后 path 以 `/api/admin/` 开头 | 注入 `X-API-Key` / `X-Internal-Key` |
| `/api/admin/wallpapers*` 或 `/api/public/wallpapers*` | 可注入 `X-COS-*`（若已配置） |
| 任意灵镜请求 | 透传客户端 `Authorization: Bearer …`（会员 JWT 由 Python `get_optional_user` / `get_current_user` 校验） |

说明：网关对 `/api/lingjing*` **不做**强制登录；是否要登录由 Python 路由依赖决定。`/api/admin/lingjing*` 在进反代前就必须是管理员。

## 7. 与 OpenAPI 对照方式

1. 打开 [`http://localhost:8000/docs`](http://localhost:8000/docs) 或 `/openapi.json`。  
2. 看「管理后台 / 公开 / 认证 / 会员」等分组下的真实 path。  
3. 在本仓库用前端 path 查上表，或直接读 `rewriteLingjingPath`。  
4. 改映射后跑：`apps/gateway` 下 `lingjing-path-rewrite` 相关单测。

当前上游 path 数量以本地 OpenAPI 为准（开发机快照约 60+）；**以运行中的 `/openapi.json` 为权威**，本文表格随网关代码演进需同步更新。
